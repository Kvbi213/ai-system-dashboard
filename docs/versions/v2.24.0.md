### 2. PROTOKÓŁ BEZPIECZEŃSTWA LIBRUS (RYGOR READ-ONLY)

Zgodnie z poleceniem operatora, dane z systemu Librus Synergia podlegają bezwzględnej izolacji:
1. **Brak narzędzi edycyjnych:** W rejestrze `agentTools` nie zarejestrowano żadnej funkcji typu `ADD_LIBRUS_*`, `UPDATE_LIBRUS_*` ani `DELETE_LIBRUS_*`.
2. **Brak akcji mutujących w promptach AI:** Zarówno prompt Vercel Serverless (`api/agent.js`), prompt klienta (`clientAiDispatcher.js`), jak i prompt lokalnego demona (`agent.js`) posiadają twardą regułę:
   > `RYGOR LIBRUS SYNERGIA (ŚCIŚLE READ-ONLY): Dane z systemu Librus (terminarz, sprawdziany, kartkówki, absencje nauczycieli oraz dziennik ocen) są WYŁĄCZNIE DO WGLĄDU. Ani system, ani asystent AI NIE POSIADAJĄ uprawnień ani akcji do edycji, dodawania ani modyfikacji oficjalnych rekordów szkolnych. NIGDY nie emituj żadnych akcji modyfikacji danych Librusa.`
3. **Deterministyczny fallback:** Gdy zapytanie dotyczy ocen lub terminarza, a połączenie LLM jest niedostępne, heurystyczny dispatcher serwuje zbuforowane dane w tabelach Markdown z wyraźnym oznaczeniem `[READ-ONLY]`.
