## 1. ZAKRES OPERACYJNY
Wdrożenie protokołu oszczędzania limitów API wyszukiwarki Brave Search, zasilenie chmury najświeższym stanem ocen Librus Synergia oraz dwupoziomowy mechanizm buforowania:

1. **Harmonogram Oszczędzania Limitów Brave Search (`modules/components/ITNewsTicker.jsx`):**
   - Całkowicie wyeliminowano agresywny interwał odpytywania API co 2 minuty (`setInterval 120000 ms`), generujący setki nadmiarowych zapytań dziennie.
   - Wdrożono silnik wyznaczania slotów czasowych (`getNewsSlotInfo`): maksymalnie 3 automatyczne zapytania w ciągu 24h:
     - Slot 10:00 (10:00:00 - 14:59:59)
     - Slot 15:00 (15:00:00 - 19:59:59)
     - Slot 20:00 (20:00:00 - 09:59:59 dnia następnego)
   - Automatyczna synchronizacja w tle obejmuje **wyłącznie pierwszą kategorię** wyświetlaną na pulpicie (domyślnie `AI & LLM`).
   - Pozostałe kategorie (np. `CyberSec`, `Startupy`, `Cloud`, `Dev`) pobierane są **wyłącznie po kliknięciu i wejściu przez użytkownika** ("on-demand").
   - Wyniki dla każdej kategorii są zapisywane w pamięci przeglądarki (`localStorage` pod kluczem `news_cache_[kategoria]_[slot]`), co sprawia, że wielokrotne przełączanie zakładek w obrębie danego slotu czasowego nie generuje żadnych zapytań sieciowych.
   - Dodano przycisk natychmiastowego wymuszenia odświeżenia (`isManual = true`), pozwalający operatorowi na ręczną aktualizację w dowolnym momencie.

2. **Dwupoziomowa Pamięć Podręczna Serwerowa (`api/news.js`, `modules/routes/news.js`):**
   - Dodano serwerowy bufor pamięciowy (`memoryCache` z TTL 1h) w punkcie końcowym Vercel Serverless (`api/news.js`) oraz w lokalnym routerze Express (`modules/routes/news.js`).
   - Wprowadzono nagłówki HTTP `Cache-Control: public, s-maxage=3600, stale-while-revalidate=7200` zabezpieczające przed powtarzającymi się zapytaniami z poziomu przeglądarek i bramek proxy.
   - Obsługa parametru `force=true` dla ręcznego odświeżania z pominięciem bufora serwerowego.

3. **Synchronizacja i Spójność Ocen Librus Synergia:**
   - Wykonano pełną replikację ocen z systemu Librus Synergia do dokumentu `librus_cache/latest` w Cloud Firestore (`void-potato-7721` / region Warszawa `europe-central2`).
   - Odzwierciedlono 21 przedmiotów, w tym 12 ze średnią i wystawionymi ocenami (Chemia 4+, Informatyka 6, UTK 5, LSK 5, SO 5, itd.) oraz średnią całkowitą 4.61.
   - Zaktualizowano i wdrożono najnowszy pakiet aplikacji na Firebase Hosting (`https://void-potato-7721.web.app`).

4. **Nowy Pakiet Testów Jednostkowych (`tests/news_ticker_quota.test.jsx`):**
   - 9 testów jednostkowych weryfikujących:
     - Precyzyjną segmentację godzin na sloty 10:00, 15:00 i 20:00 oraz przypisanie godzin nocnych/porannych do slotu wieczornego dnia poprzedniego.
     - Bezpieczny odczyt i zapis do `localStorage` z odpornością na uszkodzone dane JSON.
     - Bezwzględne wykorzystanie bufora i brak zapytań sieciowych `fetch` przy trafieniu w cache slotu.
     - Prawidłowe pobranie z API i zapisanie do bufora przy pierwszym wywołaniu.
     - Prawidłowe wymuszenie zapytania API po kliknięciu przycisku manualnego odświeżenia.
   - Łączny stan testów wzrósł do **221/221 PASS w 17 pakietach testowych**.
